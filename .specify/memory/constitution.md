# TikoTime — Project Constitution

## Context
این پروژه (TikoTime) یک اپلیکیشن Django تک‌کاربره است که فقط و فقط
روی سیستم محلی کاربر اجرا می‌شود (هرگز روی سرور/شبکه/اینترنت اجرا
نمی‌شود). این سند برای هدایت یک بازآرایی ساختاری (Refactor) نوشته
شده، نه توسعه‌ی فیچر جدید.

## قوانین سخت‌گیرانه (Non-negotiable)

1. **بدون تغییر رفتار**: این یک کار Refactor صرف است. هیچ منطق
   کسب‌وکاری، هیچ URL، و هیچ شکل پاسخ JSON نباید تغییر کند. خروجی
   هر endpoint باید قبل و بعد از تغییر دقیقاً یکسان باشد.

2. **بدون حذف قابلیت غیرمجاز**: هیچ endpoint یا قابلیتی نباید حذف
   شود مگر آن‌هایی که صراحتاً در Spec به‌عنوان «حذف تأییدشده»
   علامت خورده‌اند. موارد تأییدشده برای حذف:
   - لایه‌ی نسخه‌بندی‌شده‌ی `/api/v1/` (DRF) و وابستگی
     `djangorestframework`، چون این پروژه هرگز کلاینت دومی
     (غیر از فرانت فعلی) نخواهد داشت و روی هیچ دستگاه دیگری
     (گوشی/سرور/سیستم دیگر) هرگز اجرا نخواهد شد — فقط همین
     یک لپ‌تاپ.
   - وابستگی‌های مخصوص production که هرگز استفاده نمی‌شوند:
     `gunicorn` و `whitenoise` (شامل میان‌افزار
     `WhiteNoiseMiddleware` و بلاک `STORAGES` مرتبط با آن).
     اجرا همیشه با `manage.py runserver` انجام می‌شود.

   **مهم**: حذف DRF به‌معنای حذف «سریالایز کردن» نیست. تبدیل
   مدل‌ها به دیکشنری/JSON همچنان از طریق توابع ساده‌ی پایتون در
   `services.py`/`compat.py` (مثل `product_dict`, `sale_dict`)
   انجام می‌شود — دقیقاً همان چیزی که فرانت فعلی همیشه از آن
   استفاده کرده و تغییری نمی‌کند.

3. **تست‌ها منبع حقیقت‌اند**: بعد از هر گام، مجموعه‌ی تست موجود
   (`python manage.py test`) باید بدون هیچ تغییری در فایل‌های
   تست موجود (به‌جز حذف تست‌های مربوط به کد حذف‌شده‌ی v1)،
   ۱۰۰٪ سبز بماند. اگر تستی fail شد، پیش از رفتن به گام بعد باید
   رفع شود.

4. **تقسیم فایل بر اساس دامنه**: فایل‌های بزرگ (`services.py`,
   `compat.py`) باید به پکیج تقسیم شوند؛ تقسیم صرفاً بر اساس
   دامنه‌ی کسب‌وکار (products, sales, payments, repairs, tracking,
   calendar, reports, settings, uploads, export_import) است، بدون
   تغییر امضای هیچ تابعی. `__init__.py` هر پکیج باید همه‌ی نام‌ها
   را دوباره export کند تا نقطه‌ی صدازنی بیرونی
   (`services.xxx` / `compat.xxx`) عوض نشود.

5. **بدون وابستگی/پیچیدگی جدید**: هیچ وابستگی جدیدی (Docker, auth,
   CSRF، کتابخانه‌ی جدید) اضافه نشود. Docker استفاده نمی‌شود چون
   اجرا صرفاً محلی است. هدف نهایی، کمترین و بهینه‌ترین مجموعه‌ی
   ابزار لازم برای اجرای محلی تک‌کاربره است، نه آماده‌سازی برای
   استقرار روی سرور.

6. **جابه‌جایی فقط با تنظیمات**: تغییر محل پوشه‌ها فقط با ادیت
   مسیرهای `settings.py` (`BASE_DIR`, `STATICFILES_DIRS`,
   `TEMPLATES DIRS`, `DATA_DIR`) انجام شود، نه با تغییر منطق کد.

7. **گام‌های کوچک و قابل‌بازگشت**: هر تغییر ساختاری باید در یک
   commit مستقل انجام شود تا در صورت بروز مشکل، بازگشت به عقب
   ساده باشد.

## خارج از محدوده (Out of scope)
- تغییر منطق services (validation، محاسبات، تراکنش‌ها)
- تغییر شکل JSON پاسخ‌های `/api/*` (لایه‌ی compat)
- تغییر محتوای templates و static/js (فقط محل فایل عوض می‌شود)
- افزودن authentication، CSRF، Docker، یا logging جدید
