# TikoTime — سیستم مدیریت انبار فروشگاه ساعت

سیستم کامل مدیریت انبار، فروش، تعمیرات و سفارش‌های فروشگاه ساعت — کاملاً محلی، آفلاین، فارسی و با تقویم شمسی.

> **نسخه‌ی فعلی روی Django 5.2 بازنویسی شده است.** هر منطق کسب‌وکار در لایه‌ی سرویس (`backend/inventory/api/services/`) جمع شده و مسیرهای `/api/*` (آداپتورهای `backend/inventory/api/compat/` با همان شکل پاسخ قدیمی) روی همان سرویس‌ها بنا شده‌اند — این تنها قرارداد HTTP برنامه است.

## چیدمان سه‌بخشی

```
.
├── db/              # داده‌ی اجرایی (تحت کنترل نسخه نیست): db.sqlite3 · images/ · backups/ · exports/
├── backend/         # کد بک‌اند Django: manage.py · tikotime/ · inventory/ · tests/
│   └── inventory/api/
│       ├── services/    # تمام قواعد کسب‌وکار — تک منبع حقیقت (۱۱ ماژول دامنه‌ای + باز‌export)
│       └── compat/      # آداپتورهای /api/* با شکل پاسخ قدیمی (۱۱ ماژول + باز‌export)
└── frontend/        # دارایی‌های نمایش: static/ (css/js/fonts) · templates/
```

- **تک منبع حقیقت مسیرها**: `backend/tikotime/settings.py`. داده‌ها (`db/`) و دارایی‌های نمایش (`frontend/`) یک سطح بالاتر از `backend/` — یعنی در ریشه‌ی پروژه — قرار دارند.
- **`/api/*`** — تنها قرارداد API برنامه: همان مسیرهایی که فرانت‌اند فعلی صدا می‌زند (CRUD کامل محصولات/فروش‌ها/پرداخت‌ها/تعمیرات/پیگیری‌ها، تقویم، بکاپ، تنظیمات، خروجی/ورودی)؛ فقط آداپتور نازک روی `services.py`، بدون منطق.

## اجرا

### پیش‌نیازها
- پایتون ۳.۱۰ یا بالاتر (تا نسخه‌ی ۳.۱۴ تست شده) — اگر نصب نیست از [python.org](https://www.python.org/downloads/) بگیرید. در ویندوز حتماً گزینه‌ی «Add Python to PATH» را تیک بزنید.
- بقیه‌ی پیش‌نیازها داخل `backend/requirements.txt` هستند: Django، Jinja2 و openpyxl.

### نصب (فقط بار اول)

**لینوکس / مک:**
```bash
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
.venv/bin/python backend/manage.py migrate
```

**ویندوز (در PowerShell یا CMD داخل پوشه‌ی پروژه):**
```bat
python -m venv .venv
.venv\Scripts\pip install -r backend\requirements.txt
.venv\Scripts\python backend\manage.py migrate
```

### اجرا

**لینوکس / مک:**
```bash
.venv/bin/python backend/manage.py runserver
```

**ویندوز:**
```bat
.venv\Scripts\python backend\manage.py runserver
```

سپس در مرورگر باز کنید: **http://127.0.0.1:8000**

> بعد از اولین اجرا، همه‌چیز کاملاً آفلاین کار می‌کند و به اینترنت نیازی نیست.

### متغیرهای محیطی (اختیاری)

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `TIKOTIME_DB` | `db/db.sqlite3` | مسیر فایل پایگاه‌داده (مثلاً برای تست: `TIKOTIME_DB=/tmp/test.db`) |
| `DJANGO_DEBUG` | `1` | روی `0` هم کار می‌کند؛ دارایی‌های استاتیک در هر حالتی لود می‌شوند |
| `DJANGO_SECRET_KEY` | کلید توسعه | روی سرور حتماً یک مقدار تصادفی اختصاصی بگذارید |
| `DJANGO_ALLOWED_HOSTS` | — | میزبان‌های مجاز برای دسترسی از شبکه‌ی داخلی (همراه با `localhost` و `127.0.0.1`) |

## معرفی

TikoTime برای فروشگاه ساعت طراحی شده و سه بخش اصلی دارد:

- **انبار/محصولات** — ثبت ساعت‌های خریداری‌شده با برند، رفرنس، کد دفتر، کد انبار سایت، تأمین‌کننده، قیمت خرید، تاریخ خرید، عکس و وضعیت موجود/ناموجود.
- **فروش‌ها و پرداخت‌ها** — فروش حضوری/آنلاین با پرداخت تسویه کامل، بیعانه یا اعتباری (اسنپ‌پی/دیجی‌پی/ترب‌پی) و کد رهگیری یکتا.
- **تعمیرات، پیگیری سفارش‌ها، تقویم و تنظیمات** — با داشبورد (آمار، نمودار ۱۲ ماهه، جدول برندها) و امکان بکاپ/بازگردانی، پاک‌سازی دیتابیس و آیکون سایت.

## امکانات (بر حسب صفحه)

**داشبورد** — آمار کلی (محصولات، فروش‌ها، تعمیرات، پرداخت‌های معوق، پیگیری‌ها)، نمودار فعالیت ۱۲ ماهه (خرید/فروش/سود به تفکیک ماه)، نمودار تعداد فروش به تفکیک کانال (حضوری/آنلاین/اعتباری) با ریز سرویس‌های اعتباری (اسنپ‌پی/دیجی‌پی/ترب‌پی)، جدول برندها و فروش‌های اخیر.

**انبار / محصولات** — ثبت خرید، فیلدهای برند/رفرنس/کد دفتر/کد انبار سایت/تأمین‌کننده/قیمت خرید/تاریخ خرید/عکس، وضعیت موجود/ناموجود، فیلتر جستجو و تاریخ، ویرایش، حذف دسته‌ای، ثبت فروش مستقیم از انبار.

**فروش‌ها** — فیلترها (نوع فروش، روش پرداخت، ارائه‌دهنده اعتباری، تاریخ، جستجو)، جزئیات فروش، ویرایش، حذف، خروجی اکسل/CSV.

**پرداخت‌ها** — رسید بیعانه و رسید دستی، فیلتر پرداخت‌شده/معوق، ثبت اقساط، تسویه کامل، ویرایش، حذف دسته‌ای، خروجی.

**تعمیرات** — ثبت تعمیر با نام ساعت، کد، ایراد، تاریخ تحویل/بازگشت، مشتری، گارانتی، وضعیت، قیمت و عکس؛ تغییر وضعیت و حذف دسته‌ای.

**پیگیری سفارش‌ها (tracking)** — ثبت و پیگیری قطعه/ساعت سفارشی با کد، مشتری، قیمت، وضعیت و عکس.

**تقویم** — رویدادهای خرید/فروش/تعمیر روی شبکه‌ی ماهانه جلالی با جزئیات هر روز (خرید‌ها، فروش‌ها، تعمیرات ورودی/خروجی) و مودال جزئیات.

**تنظیمات** — تأمین‌کننده‌ها، برندها، بکاپ و بازگردانی (همراه با عکس‌ها)، پاک‌سازی دیتابیس، آیکون سایت، تصاویر یتیم.

## انواع فروش و پرداخت

- **نوع فروش:** حضوری (`person`) یا آنلاین (`online`) — مستقل از روش پرداخت است.
- **روش پرداخت:** تسویه کامل (`cash`)، بیعانه (`deposit`) یا اعتباری (`credit`).
- **تسویه کامل:** کل مبلغ فروش در لحظه ثبت شود؛ پرداخت ناقص برای فروش نقدی پذیرفته نمی‌شود (بیعانه انتخاب شود).
- **بیعانه:** مبلغ پیش‌پرداخت (بیشتر از ۰ و حداکثر برابر قیمت فروش) و یک «رسید» (Payment) ساخته می‌شود که در صفحه‌ی پرداخت‌ها ظاهر می‌شود تا اقساط بعدی ثبت شود.
- **اعتباری:** خرید حالا و پرداخت بعداً از طریق یکی از سرویس‌های **اسنپ‌پی / دیجی‌پی / ترب‌پی**؛ نیاز به انتخاب سرویس و **کد رهگیری یکتا** با پیشوند `S-` / `D-` / `T-` (مثال: `D-4546851`). کدهای رهگیری سراسری یکتا هستند.
- فقط **بیعانه** در صفحه‌ی پرداخت‌ها نمایش داده می‌شود (تسویه کامل و اعتباری رسید ایجاد نمی‌کنند)؛ رسید دستی می‌تواند از طریق `/api/payments` ثبت شود.

## ورودی و خروجی انبار

**جریان کار روزانه:** ثبت خرید ساعت → ساعت **موجود** در انبار → ثبت فروش → ساعت **ناموجود** می‌شود. حذف (یا برگشت) یک فروش ساعت را دوباره موجود می‌کند — مگر اینکه فروش دیگری برای همان ساعت وجود داشته باشد.

**ورودی/خروجی:** خروجی اکسل (xlsx) و CSV برای محصولات، فروش‌ها، تعمیرات، پیگیری‌ها و پرداخت‌ها (`/export/<نوع>.<فرمت>`)؛ ورودی محصولات از CSV/XLSX (`/api/import/products`) با قالب ورودی (`/api/import/template`)؛ ساعت‌های تکراری (بر اساس کد انبار/دفتر) به‌روزرسانی می‌شوند یا نادیده گرفته می‌شوند و وضعیت فروش (موجود/ناموجود) آن‌ها دست نمی‌خورد.

## داده و بکاپ

- `db/` شامل `db.sqlite3` و پوشه‌های `images/` (عکس‌ها)، `backups/` (پشتیبان‌ها) و `exports/` (خروجی‌ها) است؛ این پوشه‌ها gitignore شده‌اند و commit نمی‌شوند.
- **پشتیبان:** فایل پایگاه‌داده همراه با عکس‌ها (فایل جانبی `<stem>.images.zip` و دانلود بسته‌ی یک ZIP). دانلود بکاپ (`/api/backups/download/<fname>`) و آپلود/بازگردانی (`/api/backups/upload`، `/api/backups/restore`) پشتیبانی می‌شود؛ بازگردانی قبلاً یک پشتیبان خودکار می‌گیرد.
- **پاک‌سازی دیتابیس:** حذف رکوردها برای دوره‌ی جدید (با بکاپ خودکار)، قابل پیش‌نمایش از `/api/database/info`.
- توصیه می‌شود **قبل از اجرا کردن `migrate`** یک بکاپ از `db/` تهیه کنید.
- **تصاویر یتیم:** `/api/images/cleanup` فایل‌های عکس غیرارجاعی و قدیمی در `db/images/` را حذف می‌کند.

## دسترسی از شبکه‌ی داخلی و هشدار امنیتی

برای دسترسی از سایر دستگاه‌های شبکه‌ی داخلی، میزبان مورد نظر را با `DJANGO_ALLOWED_HOSTS` اضافه کنید. این برنامه **بدون احراز هویت** است و صرفاً برای استفاده‌ی **محلی/شبکه‌ی داخلی** طراحی شده است — قبل از هر انتشار عمومی یک لایه احراز هویت اضافه شود.

## تست و توسعه

- تست‌ها روی یک دیتابیس موقت اجرا می‌شوند (دیتابیس واقعی در `db/` دست نخورده می‌ماند):
  ```bash
  cd backend && TIKOTIME_DB=/tmp/x.sqlite3 .venv/bin/python manage.py test tests
  ```
- `SafeMediaTestRunner` (`backend/tikotime/test_runner.py`) پوشه‌های تصویر و بکاپ را برای کل روند تست در یک دایرکتوری موقت محصور می‌کند؛ هرگز `db/images` یا `db/backups` را نمی‌نویسد.
- برای ایجنت‌ها به `AGENTS.md` و برای مستندات طراحی به پوشه‌ی `specs/` مراجعه کنید.

## ساختار فنی (خلاصه)

- `inventory/api/services/` — تک منبع حقیقت قوانین کسب‌وکار (۱۱ ماژول دامنه‌ای).
- `inventory/api/compat/` — آداپتورهای `/api/*` بدون منطق، روی لایه‌ی سرویس‌ها بنا شده.
- `inventory/views/pages.py` — رندررهای صفحه‌ی HTML (پوسته‌ی صفحه).
- `backend/tikotime/settings.py` — تک منبع مسیرها (`DATA_DIR=db`، `STATIC_DIR=frontend/static`، `TEMPLATES=frontend/templates`).
